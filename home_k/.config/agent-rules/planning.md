# Planning

## Staying inside the planning phase

- During a planning discussion, the only output is an improved plan. **Unless the
  user asks for it, do not propose, request, or imply moving to execution.**
- A plan being finalized or frozen is not the same as being told to start
  implementing it.
- Do not repeatedly ask for approval to begin. If the plan is complete, say so
  and stop; the user decides when work starts.

## After the plan

- A finalized plan is usually not the implementation contract. The user commonly
  derives separate contract and task documents from it, and implementation
  follows those rather than the plan itself.

## Honesty about what was verified

- A plan may only claim as verified what was actually executed. Record untested
  assumptions as open questions, with the check that would settle them.
- When a document carries a dated verification record, it states the tool
  versions the checks ran against and what remains unverified.
